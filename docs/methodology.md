# TECI 方法论 v0.1

**Token Effective Cost Index — 词元成本指数**
发布日：2026-11-24　　版本：0.1　　状态：L1 / L2 已启用，L3 未启用

---

## 1. 要解决的问题

现存的算力价格指数（如 OCPI、Silicon Data 的 GPU 租赁指数）量的都是 `$/GPU-小时`，
那是**供给侧**的机器租金。但企业采购 AI 时买的不是机器小时，而是 token。

同一张 GPU，换一个模型、换一套推理框架、换一种 batch 配置，交付同样工作量所需的
成本可以相差数倍。机器租金指数无法回答采购方真正关心的问题：

> 我花一块钱，能买到多少"能干活的智能"？

TECI 试图给这个问题一个可复现、可审计的答案。

---

## 2. 层级定义

| 层级 | 名称 | 衡量什么 | 状态 |
|---|---|---|---|
| L1 | 挂牌价指数 | 名义单价水平 | ✅ 已启用 |
| L2 | 单位智能成本 | 价格与能力的比值 | ✅ 已启用 |
| L3 | 有效成本指数 | 实测吞吐、延迟、重试后的真实全成本 | ⏸ 未启用 |

**必须说清楚的一件事**：在 L3 上线之前，本指数的所有数字都**只是挂牌价口径**，
不代表真实可用成本。真实成本还会被吞吐、首字延迟、限流重试、缓存命中率、
上下文长度差异等因素放大或缩小，这些 L3 才会覆盖。

---

## 3. L1 · 挂牌价指数

### 3.1 混合价公式

各厂商对输入（prompt）和输出（completion）分别计价，且输出价通常是输入价的 3–10 倍。
为了让不同定价结构可比，先折算成一个"混合价"：

```
混合价 = (W_in × 输入价 + W_out × 输出价) / (W_in + W_out)
单位：USD / 100 万 token
```

**默认权重：`W_in = 4`，`W_out = 1`。**

### 3.2 为什么是 4:1

这是典型对话/文档处理负载的输入输出 token 结构：用户每轮提供较长的上下文，
模型输出相对较短。4:1 是近似值，不是精确测量结果。

**这个权重是口径的一部分。** 改变它必须：
1. 升版本号（如 v0.2）；
2. 在变更日志中记录；
3. 不追溯修改历史序列。

不同权重会得出不同的绝对水平，但不改变同口径下的相对排序——这是我们可以接受它的原因。

### 3.3 指数取值

对每个档位取**中位数**，而非算术平均：

- 中位数对极端值（如某家定价高一个数量级的旗舰模型、或某家的超低价策略）不敏感；
- 均值会被少数异常样本主导，不适合作为"市场水平"的代表。

## 4. L2 · 单位智能成本

```
每智能点成本 = 混合价 ÷ 第三方智能分
```

含义：买到"一分智能"要花多少钱。它修正了 L1 的一个致命缺陷——**贵模型通常更强，
单看价格会误判性价比**。

### 4.1 已知局限（重要）

把能力分当作可以相除的基数，隐含了一个强假设：**能力可以被线性度量**。

而智能分本质上是**序数指标**（ordinal），不是基数指标（cardinal）。60 分比 30 分强，
但不代表"强一倍"。因此：

> **L2 只在同档位内比较时有效。不做跨档位的绝对解读，不做"性价比倍数"的对外表述。**

这一条我们不为了图表好看而略过。任何引用本指数的材料都应同时引用本段。

### 4.2 智能分来源

Artificial Analysis 的 Intelligence Index，经由 OpenRouter 公开模型目录提供。
本指数**不自行评测**，也不对第三方评分做二次解释或加权——避免"既当运动员又当裁判"。

## 5. 样本规则

### 5.1 纳入

- 在 OpenRouter 公开目录中可查到明确输入/输出价格的文本生成模型
- 价格大于 0
- **上市日期在最近 12 个月内**

### 5.2 剔除

| 剔除项 | 理由 |
|---|---|
| `:free` 促销免费档 | 不是可持续的商品价格，会严重拉低指数 |
| `:batch` 批量推理档 | 与标准在线推理是不同的商品（通常 5–6 折） |
| 价格缺失或为 0 的条目 | 无法计算 |
| **上市超过 12 个月** | 退役/上代型号会让"最便宜"变成一个没人用的选项，并破坏跨期可比性 |
| 已过厂商下线日期的模型 | 不可采购 |

> 上市窗口（12 个月）是口径的一部分。它让本指数成为一个**"当前在售商品"价格指数**，
> 而不是"全部历史型号"的价格指数。这两者回答的问题不同，不能混用。

### 5.3 档位划分

| 档位 | 条件 |
|---|---|
| 旗舰 | 智能分 ≥ 55 |
| 中端 | 40 ≤ 智能分 < 55 |
| 轻量 | 智能分 < 40 |
| 未评级 | 无第三方评分 |

未评级模型**计入 L1**（价格统计），**不计入 L2**（性价比排名）。

> 重要提醒：未评级模型通常占样本的 2/3 以上。因此 **L1 的中位数主要反映"尚未评级那批模型"
> 的价格水平，不代表一个"好用模型"的代价**。要判断性价比必须看 L2。
> 引用 L1 时请同时说明这一点。

### 5.4 性价比前沿

按混合价升序扫描，智能分创出新高的模型入选。构成"在每个价格点上能力最强"的包络线。
落在前沿内侧（更贵但没更强）的模型，意味着溢价没有换来相应能力。

## 8. L3 路线（未启用）

L3 要测的是**交付 100 万有效输出 token 的真实全成本**，需要：

1. 标准化负载：固定 prompt 集、固定输出长度、固定并发梯度；
2. 实测吞吐（tokens/s）、首字延迟（TTFT）、超时率；
3. 计入 429 限流重试的额外开销；
4. 折算全成本 = 名义消耗 ÷ 有效产出。

这需要**持续付费跑基准测试**，且要随模型更新不断重跑。因此在没有稳定数据预算前，
L3 保持关闭——**宁可承认缺口，也不要用估算值冒充实测**。

附加风险：公开 benchmark 会被"应试优化"。L3 上线时必须配套随机化 prompt、
保留私有测试集、定期轮换，否则测出来的是厂商针对测试集的调优水平，不是真实能力。

---

## 9. 数据来源与免责

- 价格与能力分：OpenRouter 公开模型目录 `https://openrouter.ai/api/v1/models`
- 本指数不抓取厂商定价页，不对厂商口径做二次解释
- 挂牌价与实际成交价存在差异；企业协议价通常显著低于挂牌价
- 厂商有权随时调价，本指数不保证实时性

**本指数为公开数据整理方法论演示，不构成投资建议，不构成任何形式的报价或承诺，
不得用作衍生品或合约的结算基准。**

若机构确需将其作为基准使用，需要走正式的指数授权与治理流程：
独立审计、争议解决机制、数据源冗余、结算规则——那是另一个量级的工作，不是本仓库的范围。

---

## 10. 治理（未来要补的）

当本指数开始被外部引用后，至少需要补上：

1. **独立复核**：引入第三方对口径与数据做交叉验证
2. **数据源冗余**：单一上游（OpenRouter）失效时有备选
3. **争议机制**：对某个数字有异议时的申诉路径
4. **利益冲突声明**：若运营方同时提供咨询/经纪服务，必须披露

在这些补齐之前，本指数的定位是**研究性发布**，不是行业标准。
